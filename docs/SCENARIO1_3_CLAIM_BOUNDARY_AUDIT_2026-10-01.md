# Scenario 1–3 Claim-Boundary Audit

**Date:** 2026-10-01  
**Scope:** simulation methodology only.  
**Political ranking/endorsement:** none.

The original Scenario 1–3 scripts are retained as historical repository
artifacts. v0.32 does not treat their numerical outputs as empirical evidence
about real political actors or institutions.

## Scenario 1 — coalition-capture toy

The legacy script assigns different assumptions to the focal trio and the
random-trio control:

- focal collusion probability: 0.55;
- random-trio collusion probability: 0.15;
- focal leverage pressure: +0.20;
- control leverage pressure: 0;
- mitigation parameters are also stipulated.

Under the script's definition, the expected capture rate can be calculated
exactly from a Binomial(9, p) distribution. Monte Carlo is therefore not needed
to establish the direction of the comparison.

The v2 analytical script makes that circularity visible:

`simulations/scenario1_coalition_capture_v2.py`

A higher modeled rate for the focal trio is a consequence of assigning it
higher collusion/leverage probabilities. It is not independent evidence that
those probabilities describe a real institution.

The 7/12 threshold in this legacy toy is its own ordinary-majority assumption
and is separate from the main ABM's corrected 2/3 budget rule.

## Scenario 2 — emergency persistence toy

The legacy prose refers to a two-thirds extension vote, but its code does not
simulate individual votes. It uses one aggregate Bernoulli approval draw with
probability 0.55.

Therefore 0.55 must be described as an **aggregate scenario assumption**, not
an implemented two-thirds voting mechanism.

A second interpretive issue is duration. With continuation probability 0.93 per
14-day cycle, the untruncated geometric expectation is:

`1 / (1 - 0.93) = 14.2857 cycles`

or approximately 200 days. The model has a 60-cycle maximum horizon, but that
maximum must not be confused with the expected war duration generated by its
own assumption.

The v2 script makes these points explicit:

`simulations/scenario2_emergency_persistence_v2.py`

Its review/rejection probability, pressure growth and continuation probability
remain uncalibrated scenario values.

## Scenario 3 — redundancy/recovery toy

The legacy scenario assumes iid exponential recovery with mean 21 days and
changes the number of affected components from 3 to 2 to 1 as geographic
dispersion increases.

For iid exponential recovery times with mean `mu`, the expected maximum of
`k` affected components is:

`E[max] = mu * H_k`

where `H_k` is the k-th harmonic number.

With `mu = 21` days:

- 3 affected components: `21 * H_3 = 38.5` days;
- 2 affected components: `21 * H_2 = 31.5` days;
- 1 affected component: `21 * H_1 = 21.0` days.

So the direction of improvement is built into the assumed 3→2→1 affected
component construction. The simulation can check implementation noise, but it
does not independently validate geographic resilience.

The v2 analytical script is:

`simulations/scenario3_redundancy_analytic_v2.py`

The legacy toy also excludes common-mode failures, shared communications
dependencies, correlated regional disruption, and empirical recovery-time
calibration.
